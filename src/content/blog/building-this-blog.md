博客的第一版从一个几乎空白的目录开始。没有现成主题，也没有组件库，只有一个明确的目标：让阅读本身成为页面上最重要的事。

这意味着许多常见的博客元素都被暂时放下了。没有侧栏、没有文章卡片，也没有占据首屏的大图。标题、日期和摘要之间的关系，主要依靠字重、灰度与留白表达。

## 为什么选择 Astro

Astro 很适合内容优先的网站。Markdown 在构建时被转成静态页面，浏览器不需要下载一个庞大的客户端框架才能显示文章。对一台资源有限的小服务器来说，这种结果简单、直接，也容易维护。

最小的内容集合定义大致如下：

```ts
import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";
import { z } from "astro/zod";

const blog = defineCollection({
  loader: glob({ base: "./src/content/blog", pattern: "**/*.md" }),
  schema: z.object({
    title: z.string(),
    pubDatetime: z.coerce.date(),
    tags: z.array(z.string()),
    draft: z.boolean().default(false),
  }),
});
```

内容模型保持小而明确。每篇文章有标题、描述、日期、标签和草稿状态，已经足够支撑第一阶段。

## 排版先于组件

中文正文需要足够的行高，也需要比英文更克制的字重。正文区域限制在约 `720px`，一行不会长得让视线难以回到下一行；段落之间则用稳定的垂直节奏保持呼吸感。

> 如果一个边框、背景或动效不能帮助阅读，那么它大概率不应该出现在这里。

浅色模式没有使用纯白背景，深色模式也不是纯黑。略带温度的底色和低对比度正文，更适合长时间停留。

## 第一阶段的边界

第一阶段只验证最核心的阅读路径：

1. 从首页发现文章；
2. 打开一篇 Markdown 内容；
3. 在手机与桌面上舒适阅读；
4. 根据环境或个人偏好切换明暗模式。

归档、标签页、搜索和 RSS 都很有用，但它们应该在视觉方向确认之后再进入项目。先把基本体验做对，后续功能才有稳固的落点。

| 决策 | 第一阶段选择 | 原因 |
| --- | --- | --- |
| 输出 | 静态 HTML | 轻量、易部署 |
| 内容 | Markdown | 写作路径简单 |
| 交互 | 仅主题切换 | 控制客户端脚本 |
| 布局 | 单栏 | 聚焦阅读 |

第一版不是功能的终点，而是设计方向的一次清晰确认。
