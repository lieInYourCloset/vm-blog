个人服务器的维护不需要变成一份复杂的全职工作。真正重要的是建立少量可重复的习惯，并且知道出现异常时应该先看哪里。

## 从可见性开始

每次登录服务器，我会先看磁盘、内存和失败的服务。它们并不能回答所有问题，却能很快暴露最常见的异常。

```bash
df -h
free -h
systemctl --failed
journalctl -p warning -b
```

日志的价值不在于全部保存，而在于能够沿着时间找到变化。部署前后分别记录一次服务状态，通常比事后猜测更省时间。

## 更新应该可回退

更新系统前，先确认最近一次备份真的可以恢复。只看见“备份成功”并不代表数据可用；定期把一个小文件恢复到临时位置，是成本很低的验证方式。

我通常遵循下面的顺序：

- 阅读待更新的软件包列表；
- 检查磁盘空间和当前服务状态；
- 执行备份并抽样恢复；
- 安装更新；
- 重启必要服务，再检查日志与外部访问。

这套流程并不精巧，却足够明确。服务器越小，越应该让维护步骤容易理解，而不是堆叠更多工具。

## 给未来的自己留线索

一段简短的变更记录很有价值。写下日期、做了什么、为什么做，以及如何撤销。几个月后遇到相同问题时，它会比零散的终端历史可靠得多。

> 自动化的前提，是你已经理解并重复完成过这件事。

先让人工步骤稳定，再把真正重复、容易出错的部分交给脚本。
